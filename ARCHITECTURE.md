# Архитектура

## Модули

`core` зависит только от libGDX. `lwjgl3` содержит Java 21 launcher и платформенные библиотеки. Дополнительных серверов и процессов в игре нет. Дистрибутив Gradle application включает ресурсы в core JAR.

## Границы

- `Content`: типизированные определения карт, предметов сцены, NPC, диалогов; загрузка JSON и проверка ID. Ссылки дверей и реплик валидируются при запуске.
- `GameState`: только сохраняемые значения — имя, координаты, карта, часы, вид, посещения и флаги истории.
- `World`: фиксированный шаг 1/60 s, скорость 64 px/s с нормализацией диагонали, раздельные коллизии по осям, переходы, контекст реплик, идемпотентные эффекты.
- `SaveStore`: схема v1, валидация до записи и после чтения, временный JSON, атомарная замена с fallback, предыдущая исправная копия. Будущая версия отклоняется; миграций пока нет.
- `Settings`: настройки отдельно; переназначения с проверкой конфликтов.
- `PixelCanvas`: один SpriteBatch, FBO 480×270, bitmap-шрифты, кэш текстур, целочисленный вывод. Объекты вне видимой области не отрисовываются. Все GPU-ресурсы освобождаются.
- `AudioScene`: музыка и дождь с раздельной громкостью, SFX, мягкий fallback без аудиоустройства.
- `CtrlLife`: переключение контекста ввода, экраны, следящая камера, виджеты и интеграция систем. Смена режима очищает удерживаемые клавиши. Выделенные UI-классы появятся при добавлении торговли, не раньше.

## Координаты и время

Контент хранится в координатах сверху вниз, положение персонажа — точка у ног. `PixelCanvas` переводит это в координаты SpriteBatch. Ресурсы используют nearest filtering. FBO выводится с целым масштабом и полями; мышь преобразуется обратно в логические координаты.

Физика получает только фиксированные шаги. Кадровый delta ограничен 0.1 s: после зависания окна нет скачка по карте. NPC вычисляются из сохранённого игрового времени и маршрута, что исключает дублирование и зависимость от порядка загрузки. Камера сглаживается экспоненциально с зависимостью от delta, но координаты рисования округляются до пикселей.

## Проверяемость и расширение

Логические тесты не создают OpenGL. GUI-сценарий наследует приложение только в отдельном smoke source set и подаёт клавиши в тот же InputProcessor, которым пользуется launcher. В production JAR сценарий не входит.

Gate 2 добавит полноценные `Inventory`, `Economy`, `LifeNeeds` и задачи отложенного завершения по игровому времени. Перед изменением структуры сейва нужен конвертер v1 → v2 и тест миграции. Gate 3 получит совместимость компонентов. Gate 4 — настоящий lexer/parser/AST/evaluator ByteScript с детерминированными тестами и безопасной моделью выполнения без исполнения Java/системных команд.
